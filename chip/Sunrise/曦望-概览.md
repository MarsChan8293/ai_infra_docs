### 当前、主力、上一代和路线图

- **最新公开产品** 是启望 S3。官网历程写明 2026 年 1 月发布，首页把它作为 Agent 时代核心产品。
- **已公开量产主力** 是启望 S1 和启望 S2。官网明确写出两者量产，外部报道对 S2 给出万片级量产口径。
- **上一代关系** 可以按 S1 → S2 → S3 理解。S1 重点是视觉和多模态推理，S2 转向大模型推理，S3 转向大模型和智能体推理。这是产品定位上的代际关系，不代表每一代的微架构完全兼容或由同一芯片直接升级。
- **后续路线图** 当前官网导航没有 S4、S5 产品页。媒体转述 2026 年融资用途时提到 S4、S5 研发，但本次已核验资料没有找到可直接引用的曦望官方路线图或规格承诺，因此标为未确认。
- **停产** 没有找到 S1 或 S2 的停产、停售、EOL 或软件维护截止公告。量产不等于仍在接单，官网也没有公开生命周期政策。

### 推理数据搬运算子的证据边界

用户关注的 Search、Reduce、Top-k、Address、Route、Gather、KV 和跨卡通信，在公开资料中并没有同等强度的硬件证据。下面按最宽松且可复核的口径记录。

| 能力 | 公开证据 | 证据等级 | 目前不能确认的实现 |
| --- | --- | --- | --- |
| Search | 未见 S1、S2、S3 产品页或公开下载文档明确描述搜索单元、检索指令或检索基准 | 未确认 | 不能把“推理 GPU”或“大模型推理优化”解释成硬件 Search |
| Reduce | 未见公开的归约单元、跨线程归约指令或 Reduce 性能数据 | 未确认 | 不能确认是否由 GPGPU 通用算子、编译器融合或通信库完成 |
| Top-k | 未见 Top-k 单元、排序网络、选择算法或模型测试 | 未确认 | 不能据此声称对 MoE 路由或采样有专用硬件加速 |
| Address | S3 只公开大容量内存和减少系统内存交换 | 公司主张涉及数据交换，地址机制未公开 | 没有全局地址空间、虚拟地址、页表、IOMMU、地址翻译或远端寻址证据 |
| Route | 官网提到 MoE 的计算感知通信拓扑和大 EP 部署 | 系统层公司主张 | 没有路由器硬件、专家选择单元、token dispatch 格式或拥塞控制证据 |
| Gather | 未见 indexed gather、DMA gather、分散聚集指令或带宽测试 | 未确认 | 不能把“大容量显存”直接解释成 Gather 加速 |
| KV | S3 页面称减少显存与系统内存之间交换，支持长上下文和百万级 Token | 公司主张，属于系统目标和产品叙事 | 没有 KV cache 格式、页式管理、量化、复制、分片、压缩、容量占用或命中率数据 |

从这些材料可以提出一个谨慎的架构假设。曦望正在把推理的瓶颈从单卡算力扩展到内存容量、Host-Device 通路、阶段调度和 MoE 互联，S3 与 SC3-256 的公开叙事都支持这一方向。公开材料还不足以证明它已经实现了独立的 Programmable Retrieval Plane，也不足以证明 Search、Top-k、Gather 或 KV 管理有专用硬件路径。

## 软件栈与开发入口

### SIRE

SIRE 的全称是 Sunrise Integrated Running Environment。官网把它拆成四层。

| 层 | 官网公开内容 | 公开程度 |
| --- | --- | --- |
| GPU | 启望系列 GPU | 产品层级描述 |
| SoC 系统软件层 | S3 页面和产品页的 SIRE 图示 | 未公开模块和 API |
| 驱动与运行时层 | 硬件接入和运行时 | 未公开驱动版本、设备模型、内存 API 和调度接口 |
| 编译器与算子库层 | 自研编译工具链、算子库；S2 提到 TANG 编程模型 | 未公开编译器文档、算子覆盖率和性能报告 |
| 框架与生态应用层 | PyTorch、vLLM、SGLang；S3 另列 LightLLM、LightX2V | 官网兼容性主张，缺少版本矩阵和复现仓库 |

S3 官网还列出 DeepSeek、Qwen、Llama、Stable Diffusion、Flux、Wan、Seko、hunyuan3D、CNN 和语音模型。这里的“适配”只说明官网宣称存在适配，不等于每个模型在每个精度、并发、上下文长度和卡型上都已公开验证。

S2 页面使用“与主流 AI 开发生态高度兼容”和“无缝迁移”，S3 页面使用“兼容第三方 GPGPU 计算软件平台，支持零代码无缝迁移”。已核验官网没有给出完整 CUDA API 兼容清单、二进制兼容等级或迁移限制，因此不能把媒体常见的“完全兼容 CUDA”写成已核实事实。
