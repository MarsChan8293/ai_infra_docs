# Huawei / 华为昇腾 — Ascend 910B

- 研究截止日：2026-09-05
- 核验日期：2026-09-05
- 厂商：华为技术有限公司 / 华为云
- 产品层级：AI 加速芯片 / NPU；公开资料同时出现板卡、服务器、云资源和软件栈口径
- 厂商总览：[华为昇腾](./华为-概览.md) · [[华为-概览|图谱总览]]
- 页面范围：只判断 Ascend 910B 芯片及其直接证据。Ascend 910、910C、Atlas 服务器、CloudMatrix 超节点和华为云实例分别记录，不把相邻对象的规格回填为 910B 芯片规格。

## 一句话结论

Ascend 910B 是昇腾 910 代际中仍被华为云和昇腾软件栈持续识别、用于训练和推理的主流数据中心 NPU。华为官方 2025 年路线图明确把 910B/910C 作为 950 系列的前代比较对象，华为云 ModelArts API 也把 `ASCEND_SNT9B` 明确列为“昇腾910B芯片”；但截至 2026-09-05，华为没有公开一份可核验的 910B 芯片级完整数据表，因此容量、带宽、峰值算力、制程、TDP 和芯片量产批次均不能用 910 或 910C 的数字补齐。

## 产品定位与对象边界

### 已确认事实

1. 华为在 2025-09-18 的全联接大会演讲中回顾了 2018 年 Ascend 310、2019 年 Ascend 910，并把 Ascend 910B/910C 与即将推出的 950 系列并列比较；演讲还称华为云团队已将 910B/910C 的推理能力提升到客户基本需求。该材料确认了产品代际和使用语境，但没有发布 910B 的芯片级规格表。[华为 2025 路线图演讲](https://www.huawei.com/cn/news/2025/9/hc-xu-keynote-speech)
2. 华为云 ModelArts API 参考将 `ASCEND_SNT9B` 定义为“昇腾910B芯片”，与 `ASCEND_SNT9`（910）和 `ASCEND_SNT3`（310）分列。这是华为云资源类型证据，不等于每个区域都有公开可购买的独立 910B SKU。[ModelArts API 参考](https://support.huaweicloud.com/api-modelarts/10%20ModelArts_API%E5%8F%82%E8%80%83%207.3.1-pdf.pdf)
3. 华为云官方软件仓库持续发布 `ascend-cann-910b-ops` 组件，例如 CANN 8.5.0、9.0.0 及后续 9.x 目录。这确认了软件栈对 910B 的持续适配；软件包存在不能单独证明芯片出货量或单卡现货。[CANN 软件目录](https://repo.huaweicloud.com/ascend/repos/conda/linux-64/)
4. 华为云技术社区的 LMDeploy 实践记录使用 `Huawei Ascend 910B (64G)` 环境，说明 64G 这一板卡/云资源口径在实际开发环境中出现；该文章不是芯片数据手册，不能据此断言所有 910B 封装都具有 64GB 或同一 HBM 配置。[华为云社区实践](https://bbs.huaweicloud.com/blogs/436917)

### 不能跨层级推导的内容

- `64G` 出现在华为云社区实践和部分云/模型资源描述中，当前不能确认它是裸芯片容量、封装容量、加速卡可用容量还是虚拟资源展示值；本页不把它写入“芯片级规格”。
- Atlas 800T A2、Atlas 900、CloudMatrix384 等是服务器、超节点或云服务对象；它们的卡数、服务器功耗、RoCE 端口和系统带宽不能反推 910B 单芯片的 TDP、封装内存或 die-to-die 互联。
- CANN、AscendC、HCCN、MindIE 和 vLLM 适配证明软件栈支持，不自动证明芯片内置 Search、Top-k、KV Page Translator 或 Indexed Gather DMA。

## 架构与检索路径映射

公开资料足以确认 910B 是可被 CANN/Ascend 生态使用的训练/推理 NPU，但不足以把它描述成附件设想的 Retrieval GPU。下表中的“间接帮助”是基于公开软件/系统能力的架构分析，不是 910B 专用硬件承诺。

| 附件动作 | 直接硬件证据 | 间接帮助 | 没有解决/证据不足 |
|---|---|---|---|
| Search / Indexer | **公开资料未确认** | 通用 NPU 计算和软件算子可承载扫描或向量计算 | 没有公开 Indexer、ANN 搜索或专用检索 SRAM |
| Select / Local Top-k | **公开资料未确认** | CANN 算子库可能承载排序/规约 Kernel | 没有公开芯片级 Top-k/merge-top-k 指令或单元 |
| Move | **公开资料未确认** | CANN、HCCN 和服务器网络可提供数据搬运软件路径 | 没有公开按 KV page 列表驱动的 Indexed Gather DMA |
| Route / 跨卡 | **系统/软件层有证据**：华为云文档和实践出现 HCCN、RoCE、集群卡间互通 | 可用于多卡训练/推理的通信编排 | 这不等于 Retrieval-aware Route，也没有公开候选路由或通信量数据 |
| Address | **公开资料未确认** | 统一运行时、设备资源枚举和通信软件可支撑地址管理 | 没有公开 KV page table、物理地址描述符链或持久化 Gather queue |
| 离散 KV Gather | **公开资料未确认** | 通用向量/张量算子可以实现软件 Gather | 没有芯片级访存合并、page-aware Gather 或端到端 KV 延迟数据 |
| Global Top-k / Reduce | **公开资料未确认** | 集群通信库可能承载 Reduce/AllReduce | 通信库原语不等于精确 Top-k；跨卡 payload 和尾延迟未公开 |
| TPOT / TTFT / Tokens/J | **公开资料未确认** | 910B 云环境可以运行 LMDeploy 等推理软件 | 没有统一模型、上下文、batch、软件版本和功耗边界的可复现实测 |

## 未确认项与避免误读

1. **910B 不是 950。** 950 白皮书中公开的 SIMD/SIMT、128B sector、NDDMA、2TB/s Unified Bus 和 HiBL/HiZQ 口径属于 950 系列，不能因为 950 的路线图把这些能力回填给 910B。
2. **910B 不是 910C。** 华为官方将两者并列提及；910C 随 Atlas 900 超节点部署的系统事实，不等于 910B 的芯片规格或部署规模。
3. **64G 不是已确认的芯片 HBM 容量。** 目前核验到的 64G 证据来自云社区实践/资源描述，缺少公开的 910B 芯片数据手册和完整封装映射。
4. **软件适配不是量产证明。** CANN 仓库、ModelArts API 和社区实践说明开发/运行路径存在，不能替代流片、量产、出货、客户部署或云库存证据。
5. **通用通信不是 Retrieval Route。** HCCN/RoCE/AllReduce 等系统能力可用于多卡，但公开资料没有证明它们能按候选价值路由 KV 或执行 Global Top-k。

## 对下一代 Retrieval GPU 的可借鉴点

- **可借鉴**：保留面向训练和推理的统一软件资源抽象，让同一套算子/运行时能够覆盖不同部署形态。
- **只能类比**：将 HCCN/RoCE 等通信路径作为跨卡数据移动底座，但要另行加入 candidate descriptor、KV page table 和精确合并语义。
- **不宜照搬**：在缺少公开芯片级访存和缓存证据时，不应把云环境中的 64G、CANN 算子支持或整机网络规格写成专用 Retrieval 硬件。
