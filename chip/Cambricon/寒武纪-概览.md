## 结论先行

1. 截至研究截止日，寒武纪官网公开产品导航明确列出的客户产品仍是思元370系列加速卡、思元270系列加速卡、思元220系列边缘模组/加速卡，以及 Cambricon-1M、Cambricon-1H 终端智能处理器 IP。官网还保留玄思1000整机和历史产品合作伙伴目录。[S1][S2][S3]
2. 公开资料可确认的芯片家族包括 MLU100/思元100、MLU220/思元220、MLU270/思元270、MLU290/思元290、MLU370/思元370；IP 家族包括 1A、1H、1M。官方软件文档还公开了 CE3226、MLU570、MLU580、MLU590 这些硬件/架构目标，但没有同步给出完整的公开产品手册、销售状态或量产日期。[S4][S5][S6]
3. 最新明确披露的云端新品是思元590：2022-09-02 官方 WAIC 文章称其“在研”、采用 MLUarch05，内存容量和带宽较大、PCIe 接口升级。后续官方 CNNL/CNToolkit 文档确实出现 MLU590、MLU570 和 MLU580 支持，说明已有软件适配对象；截至截止日仍未找到官方完整规格页、正式发布公告、流片公告、量产公告、客户出货公告或云实例目录，因此不能写成“已量产上市”。[S5][S6]
4. MLU690/思元690：截至 2026-09-01 在寒武纪官网、开发者社区和公开 SDK 文档中未检索到可核验的一手资料，状态为“公开资料未确认”，不能纳入已确认产品族。
5. “当前主力”不能仅凭官网导航或财报推断具体型号。2026 年半年报只披露云端智能芯片、基础系统软件和硬件平台仍在“迭代研发中”，没有按 MLU 型号披露收入。较稳妥的判断是：思元370是当前官网最完整、可直接查规格和开发文档的公开云端产品；思元590及 MLU500 系列属于软件适配/研发信号，不足以证明商业主力。[S7]

## 证据等级与状态口径

- **A：官方产品页/官方新闻稿/交易所公告**。可确认公开型号、规格或公司自己声明的阶段。
- **B：官方 SDK、官方开发者文档或官方论坛**。可确认软件支持、架构编号、板卡映射或开发者可见对象；不能自动证明销售、量产或客户部署。
- **C：厂商主张或厂商测试**。数字可记录，但应标为厂商主张，不能替代独立测试。
- **未知**：公开资料未确认。没有把“未找到”写成“没有”。

生命周期字段严格拆开：首次披露、正式发布、流片、送样、量产、出货、客户部署、云端可用、路线图/在研、停产。寒武纪很少在公开页面逐项披露全部阶段，所以未有一手证据的字段均写“公开资料未确认”。

## 二、形态分层：芯片、板卡、模组、整机、服务器、云

| 层级 | 已确认对象 | 应如何理解 |
|---|---|---|
| 芯片/SoC | MLU100、MLU220、MLU270、MLU290、MLU370 | 芯片是板卡或模组上的核心硅片；思元名称是寒武纪云/边产品品牌，不等于板卡型号 |
| 终端 IP | 1A、1H、1M | IP 是可授权的处理器实现方案，不是寒武纪自有 PCIe 卡；官方半年报对“智能处理器 IP”的定义包含核心架构、代码和文档 |
| PCIe 加速卡 | MLU100-C3/D3、MLU270-S4/F4、MLU270-D4/X5K、MLU370-S4/S8/X4/X8 | 板卡通过 PCIe 接入服务器。MLU100-C3/D3、MLU270-D4/X5K 在官方硬件合作伙伴目录出现，但当前没有同等完整的产品详情页，应视为历史/适配 SKU |
| OAM/加速模块 | MLU290-M5 | MLU290-M5 是搭载思元290的 OAM 形态加速卡/模块；不要把它当作另一颗芯片 |
| 边缘模组 | MLU220-SOM、MLU220-M.2 | SOM 是信用卡大小的边缘 SoC 模组；M.2 是边缘加速卡，产品层级和热设计目标不同 |
| 加速器整机/盒子 | 玄思1000、MLU-X1000 | 玄思1000在 2U 机箱中集成 4 颗思元290，支持 4 张 MLU290-M5；MLU-X1000是官方历史硬件产品目录中的 2U Accelerator Box 名称。整机不是芯片，也不是云服务 |

## 四、对 Search / Reduce / Top-k / Address / Route / Gather / KV / 跨卡的架构关系

这里把“官方事实”和“研究判断”分开。寒武纪公开材料大多是产品规格和软件算子文档，没有一份公开白皮书宣称某款 MLU 内置专用 MoE 路由器、全局 KV 地址空间或独立 Top-k 硬件单元。

| 推理环节 | 官方可确认事实 | 研究判断与边界 |
|---|---|---|
| Search | CNNL 文档的算子/版本说明出现 `cnnlSearchSorted`；还出现 `cnnlUnique`、`cnnlCummax` 等排序/索引相关算子 | 这说明软件栈覆盖搜索/排序类原语，不等于硬件有独立搜索阵列。实际延迟取决于算子版本、数据布局和是否落到片外内存 |
| Reduce | CNNL 公开 `cnnlReduce`；CNCL/Horovod 官方材料公开 SEND、BROADCAST、REDUCE 和 AllReduce 等集合通信 | Reduce 同时存在“片内/单卡算子规约”和“跨卡梯度规约”两条路径。后者更依赖 CNCL 拓扑与链路，而非只看 TOPS |
| Top-k | CNNL 版本说明出现 `cnnlTopK`/`cnnlTopKTensor`/`cnnlTopKTensor_v3`，并记录了 MLU590 某些 TopK 接口的限制或精度问题 | Top-k 是公开软件能力，但支持存在架构/版本边界；对 MoE 或检索推理做容量估算时不能把 Top-k 当作所有 MLU 都有同等硬件吞吐 |

### 架构含义的简化推导

对长上下文或 MoE 推理，寒武纪资料能支持的保守推导是：

`算子执行（CNNL） → 索引/重排（Gather / Scatter / Index） → 单卡规约（Reduce / Top-k） → CNCL 按拓扑选择链路 → 跨卡规约或交换`

这条链路中，370的 LPDDR5 与 MLU-Link 是有数字的一手事实；Search、Top-k、Gather、Reduce 是公开软件原语；KV分页、全局地址、专用路由单元和端到端 token 交换吞吐仍属于公开资料未确认或需要独立测试的部分。

## 五、软件与生态边界

寒武纪公开 NeuWare 采用“云边端一体、训推一体”定位，包含驱动、运行时、算子库、编译器、MagicMind、CNNL、CNCL、CNTOPO 等组件。官方开发者文档还提示 SDK 下载对企业用户开放，当前公开可见的完整课程与产品开发资料主要集中在 MLU370/200 系列。[S28][S29]

因此，软件支持矩阵可以证明“某个硬件目标被工具链识别、某些算子有实现或限制说明”，但不等同于：

- 该芯片已经正式发布；
- 该板卡已经量产或可购买；
- 云厂商已经提供实例；
- 某项算子具备专用硬件单元；
- 某个厂商自测数字可在任意模型、任意 batch 和任意多卡拓扑复现。
